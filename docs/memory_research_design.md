# Active long-term memory + research scratchpads — design (v0, 2026-07-22)

_5-agent design (1 lens, conclude-and-store, failed schema retry — noted as a gap to finish in implementation)._

## Summary
A research task IS a topic. The design extends saandal's existing topic record (topics.py) with three new fields (research:bool, plan:[item], scratch:[note]) and two new markdown sections (## plan, ## scratchpad) inside the SAME <wiki>/topics/t<NNNNN>.md file — inheriting write-through persist (_persist_topic:627), dormant rehydrate (_rehydrate:684), LRU-evict (_evict_if_needed:393), curation-on-close (_curation_note:1064), and the merge_inboxes never-scans-topics/ guarantee for free. NO new hook, middleware, module, or store is added. All four features (research scratchpad, SOUL self-knowledge, active recall, conclude-and-store) are strict supersets behind default-off sub-flags under tools.tool_search.topics.*; with every flag off, build_topic_block, _serialize_topic_md, and _BLOCK_HEADER are byte-identical to today and the two anti-disclosure regression assertions (test_topics_unit.py:118-120 and 686-688) stay green. The capture path already exists: _tp_post_llm (1193) already calls selfheal.harvest_findings + _to_provenance every turn, so F1-forced research searches already flow into rec['findings'] — the new code only adds a second bucket and a keyword-overlap reconcile. The anti-disclosure tension is resolved by SPLITTING the two prohibitions _BLOCK_HEADER conflates — (i) never name the thread/topic-number, (ii) never narrate the plumbing — relaxing (i) only on a dormant resume (the t#NNNNN badge is already visible on the user's prior replies) while keeping (ii) absolute; continuity is attributed to *remembering*, which is honest.

## Architecture
RESEARCH TURN (user: "/research compare pnpm vs npm install speed"): 1) _tp_pre_llm(1155)->_route(966)->_parse_override(925): a new _RESEARCH_RE matches and returns ("research", goal). 2) _apply_override(945) calls _open_topic(367) (now initializing plan:[], research:False, scratch:[]), sets rec['research']=True, calls _seed_plan(cfg,rec,goal). 3) _seed_plan: if research_decompose=llm, ONE ctx.llm.complete_structured (clone of _classify_llm:846; {items:[...]} schema, temp 0, max_tokens~160, purpose='router.research_plan') -> up to plan_max_items items {text,status:'open',src:''}; on failure or decompose=off -> single item = raw goal. 4) _route finishes: _rehydrate no-op (fresh), _persist_topic writes the new '## plan' section, memoizes _tp_turn. 5) build_topic_block(1104): rec['research'] true -> appends "Research plan (work the open items; call web_search for each, then synthesize):" rendering open [ ] / done [x] items under a plan_token_cap sub-budget CARVED FROM (not added to) block_token_cap; returns {'context': block} appended to the current-turn user message (turn_context plugin_user_context — system prefix stays cache-stable). 6) The MODEL runs its in-turn tool loop (web_search per item) and synthesizes; pre_llm_call does NOT re-fire inside the loop, so the model tracks intra-turn progress in its own context. 7) _tp_post_llm(1193): the EXISTING harvest_findings(1223)+_to_provenance(1224) fold url-bearing findings into rec['findings']; NEW _reconcile_plan(rec,new_findings) keyword-overlaps (reusing _keywords:301 + the len(a&b)/len(a) scoring from _cold_match_dormant:766) each sourced finding against each OPEN item, flipping to done+stamping src when overlap>=plan_overlap(0.34); an opt-in PLAN-DONE:<text> regex off assistant_response closes url-less items; if scratchpad=on a second bucket captures the non-src harvest lines _to_provenance rejects (peeled via selfheal.strip_tool_result_wrapper) into rec['scratch']; _persist_topic rewrites ## plan/## scratchpad. 8) NEXT turn's build_topic_block shows freshly-checked [x] items; when 0 open remain (or /research done) the plan section is swapped for "All items researched — synthesize a final answer now, citing each [src: url] below:". RECALL TURN (same thread resumes months later): 1) _tp_pre_llm->_route: no override/memo; opens empty or classify->_resolve_new(585)->_cold_match_dormant(749) matches the dormant tid->_ensure_topic_loaded+_rehydrate loads facts/findings/plan/scratch; the dormant-reopen branch sets transient rec['_resumed']=True (every warm path — single-open continuation 987, classify-route 993, fresh _open_topic 596, override new/route branches — explicitly sets it False so a long-lived rec never carries a stale flag). 2) build_topic_block(rec,cfg,voice=_active_voice.get(session_id,False)): resumed and resume_surface=on -> header=_BLOCK_HEADER_RESUME (relaxes (i), keeps (ii)); after the recent/anchor section append ONE invite line naming t#NNNNN (suppressed to '' in voice sessions since TTS would read it aloud, mirroring badge_for's _active_voice guard); if active_recall=on append the fact-surfacing permission line with facts capped at recall_facts_max. 3) The model opens its reply naturally acknowledging it is picking the thread back up, attributes continuity to remembering (SOUL paragraph makes this honest), may name t#NNNNN, and never narrates the injected block. 4) _tp_post_llm folds the turn back; rec['_resumed'] is transient and never serialized because _serialize_topic_md(480) enumerates a FIXED key set.

## Scratchpad design
The research scratchpad is a PLAN-checklist + captured-notes working memory layered onto the existing topic record — NOT a new <wiki>/scratchpads/ subtree (rejected: it would re-implement persist/rehydrate/evict/curation that topics already gives). Two complementary buckets, both new '##' sections in the same t<NNNNN>.md: (A) PLAN — the goal decomposition. Item shape {text:str, status:'open'|'done', src:str}. Serialized in _serialize_topic_md(480) BELOW ## findings as '## plan' with '- [ ] text' / '- [x] text [src: url]'; parsed in _parse_topic_md(510) via _PLAN_RE = ^-\s*\[( |x)\]\s*(.*?)(?:\s*\[src:\s*(\S+?)\])?$; mirrored in _rehydrate(684) so a dormant research task resumes with its checklist intact. Detection is three tiers cheapest-first, reusing _parse_override/_OVERRIDE_RE(922): (1) explicit /research <goal> via a new _RESEARCH_RE = ^/research(?:\s+(.*))?$ — deterministic, zero false positives, the PRIMARY path; (2) /research done|status sub-commands for synthesize/inspect; (3) optional research_auto (default off): a NEW research_intent() in verify_route.py — a MULTI-item detector (verbs {research,compare,find out,look into,'pros and cons of','options for'} AND >=1 wh/list cue) that must NOT reuse attribution_recency_intent(verify_route:94) which fires on single checkable facts and would mislabel every citation question as research; auto only promotes an already-open topic on its FIRST turn. STATE MACHINE: the PLUGIN is source of truth, the model does NOT edit the md (model-authored markdown reformats/renumbers). _reconcile_plan runs in _tp_post_llm right after the existing harvest loop, keyword-overlapping sourced findings against open items. (B) SCRATCH — short non-src notes / open questions that harvest_findings(selfheal:1745) yields but _to_provenance rejects (no url). Second bucket off the SAME harvest, peeled with strip_tool_result_wrapper (never storing raw untrusted_tool_result envelopes), stored as short first-lines only. Serialized as '## scratchpad', injected in build_topic_block AFTER findings so the existing tail-truncate drops it before src-findings. INJECTION: build_topic_block appends the plan under its own plan_token_cap(180) sub-budget so a long checklist cannot starve the summary/findings the block_token_cap guards; the model carries the checklist through its in-turn tool loop and the plugin reconciles in post_llm so the NEXT turn shows checked items (honest one-turn-lag cross-turn tracking, since pre_llm does not re-fire inside a tool loop).

## Self-knowledge + active recall
CORE RESOLUTION: _BLOCK_HEADER(1094) conflates two prohibitions — (i) 'do not mention these notes, the thread, or any topic number' and (ii) 'never say it came from notes, memory, a system prompt, or context you were given'. Active recall RELAXES (i) on a dormant RESUME while KEEPING (ii) absolute. Why (i) is honest to relax: on a warm turn the model already sees its own prior replies carrying the badge_for 't#NNNNN' tag in conversation_history, so it can honestly name the number WITHOUT the silent block ever leaking it — the number only needs INJECTING on a dormant resume where the badged replies fell out of the visible window. MECHANISM: (1) new flag resume_surface (default off) added to DEFAULTS + _FLAG_KEYS(69) — _cfg(161) already normalizes it, no other plumbing. (2) transient non-serialized rec['_resumed'] set True only on the dormant-reopen branch of _resolve_new(585)/_apply_override(945-route) and explicitly False on EVERY warm path in _route (single-open 987, classify-route 993, fresh open) so a long-lived rec cannot leak the id on a warm turn; it never reaches disk because _serialize_topic_md(480) enumerates a fixed key set. (3) build_topic_block gains a 3rd positional voice=False (keeps the 2-arg test calls valid): header = _BLOCK_HEADER_RESUME if (resumed and resume_surface=='on') else _BLOCK_HEADER, and after the anchor it appends ONE invite line with tag = '' if voice else ' (t#%05d)'%id (voice guard drops the spoken 't#00042' but keeps the verbal acknowledgment, parallel to badge_for's _active_voice suppression). (4) NEW constant _BLOCK_HEADER_RESUME (verbatim): "[Background continuity notes for a thread you are RESUMING after a gap — NOT part of the user's message and NOT a question. You genuinely remember this thread; treat it as your own recollection. You MAY acknowledge the thread and refer to it by the t#NNNNN tag the user already sees on your replies. But NEVER reveal the mechanism: do not say a note, memory, system prompt, or context was given to you this turn, and do not say you 'looked it up' — attribute your continuity to remembering your earlier conversation with them.]" The existing _BLOCK_HEADER is UNCHANGED (keeps 'attribute it to earlier'/'never say it came from notes'/'do not mention' — tests 118-120 and 686-688 stay green). EXACT SOUL.md PARAGRAPH (verbatim, new paragraph after the Voice line in ~/.hermes/SOUL.md): "Long-term memory: you carry memory across conversations. Threads you've worked on are recalled to you automatically when they become relevant again — you don't fetch or read them, you simply find you already remember. So answer from continuity: 'earlier we were working on X' is honest. Each thread carries a short tag (t#NNNNN) shown on your replies; the user may refer to a thread by it and you may name it to help them reconnect. Two honesty rules hold: never fabricate a memory — if you don't actually recall something, say so; and never narrate the plumbing — don't claim a note, memory file, system prompt, or injected context was handed to you this turn. From your side it is simply remembering; describe it that way. If memory is quiet (nothing recalled), just proceed normally — don't announce that you have or lack it." This resolves the tension precisely: the model may speak of REMEMBERING and name the shared t#NNNNN badge (both honest), user-stated FACTS surface as 'earlier we discussed / you told me' (honestly attributable), tool FINDINGS stay under [src:] discipline and are NEVER surfaced as 'you told me' — the anti-disclosure rule survives as the mechanism-only clause (ii). The paragraph is deliberately conditional ('when relevant', 'if memory is quiet, proceed normally') so it stays honest even with topics.enabled=off — nothing recalled makes it vacuously true (the fail-safe seam). ACTIVE RECALL (separate flag active_recall, default off) is a FRAMING change not a new store: it appends a permission line to build_topic_block — 'You MAY proactively surface a known fact when relevant, phrased as recalling what THEY told you' — promoting the already-injected user-stated facts (capped recall_facts_max=5) WITHOUT weakening _BLOCK_HEADER.

## Conclude-and-store
Conclude-and-store folds finished research into the curated wiki through the EXISTING inbox pipeline — the plugin still NEVER writes wiki/, index.md, or log.md directly (the non-negotiable write rule); tools/merge_inboxes.py remains the sole wiki writer and the human merge pass is the gate for anything durable. THREE tiers: (1) ON CLOSE (/topic close or /research done): extend _curation_note(1064) to emit the plan as a '## checklist' block (done items with their [src: url] and any still-open loose ends) plus the scratch notes, alongside today's summary/facts/findings, into inbox/hermes/topic-t<NNNNN>-<slug>.md with the existing 'target: jobs/<slug>' frontmatter (jobs is a valid merge SECTION); merge_inboxes folds it into human-reviewed wiki/ exactly like today. (2) INCREMENTAL (flag autostore, default off): _extract_facts(cfg,rec,user_message,assistant_response) — one bounded ctx.llm.complete_structured cloning _classify_llm(846) (PluginLlmTextInput + json_schema, temperature 0, timeout, purpose='router.topic_curate') that extracts first-person DURABLE user facts, AMORTIZED via the same rec['turns'] % autostore_every guard already used by summarize_every(1236) so steady-state stays <=2 aux calls/turn (classify + curate); when autostore=on it also drops an incremental _curation_note (idempotent — _atomic_write same basename overwrites, so re-firing does not spam inbox). Register aux task router_topic_curate alongside router_topic_classify(1288). (3) The synthesize directive (build_topic_block at 0 open items) drives the model to produce the final cited answer in-turn, whose url-bearing findings the existing harvest path captures into rec['findings'] for the eventual note. Guard: _extract_facts is schema-constrained first-person durable-only at temp 0, default OFF, inbox-only, amortized — the mitigations against hallucinated/over-captured PII reaching curated memory. Note SOUL alignment: until the SOUL memory paragraph lands (Phase R3), autostore-surfaced facts must remain attributable as 'earlier in our conversation', consistent with verify-discipline.

## Config flags
- tools.tool_search.topics.research (flag, default off) — master sub-flag for the research scratchpad; off => topics byte-identical to today
- tools.tool_search.topics.research_auto (flag, default off) — heuristic promotion of an already-open topic to research on its FIRST turn only, via research_intent() in verify_route.py
- tools.tool_search.topics.research_decompose (llm|off, default off) — the one-shot plan-seeding LLM call; off => single-item plan = raw goal
- tools.tool_search.topics.plan_max_items (int, default 6) — cap on seeded plan items
- tools.tool_search.topics.plan_token_cap (int, default 180) — sub-budget CARVED FROM block_token_cap for the injected checklist
- tools.tool_search.topics.plan_overlap (float, default 0.34) — keyword-overlap bar for finding->item reconcile (matches _ROUTE_MIN_OVERLAP)
- tools.tool_search.topics.scratchpad (flag, default off) — capture+inject non-src research notes as a second bucket off harvest_findings
- tools.tool_search.topics.resume_surface (flag, default off) — gates the dormant-resume acknowledgment line + _BLOCK_HEADER_RESUME + injected t#NNNNN
- tools.tool_search.topics.active_recall (flag, default off) — promote user-stated facts to a proactive-surface permission line (never relaxes _BLOCK_HEADER)
- tools.tool_search.topics.recall_facts_max (int, default 5) — cap on surfaced facts
- tools.tool_search.topics.autostore (flag, default off) — amortized LLM first-person fact extraction + incremental inbox curation note
- tools.tool_search.topics.autostore_every (int, default 4) — amortization cadence, mirrors summarize_every
- tools.tool_search.topics.block_token_cap (existing int, default 250; bump to ~320 only when research|scratchpad|active_recall on — remains the SINGLE combined cap enforced by the existing tail-truncate at 1143)
- existing unchanged gates: tools.tool_search.topics.enabled (master kill-switch), .badge, .classify, .summarize, .summarize_every; tools.tool_search.force_verify (F1, verify_route)

## Top risks
- **pre_llm_call fires once per turn, not inside the tool loop, so a checklist item completed mid-turn is only re-rendered as [x] on the NEXT turn's injection — the injected block can lag reality by one turn.** → Stated contract: the model tracks intra-turn progress in its own context and the plugin reconciles in post_llm_call so the next turn's block is fresh; acceptable and documented, not a correctness bug.
- **Keyword-overlap _reconcile_plan can mis-match a finding to the wrong open item, or miss a correctly-found item whose phrasing diverges from the seeded text (same failure mode already accepted for _cold_match_dormant/dormant resume).** → Opt-in model-authored PLAN-DONE:<text> line as a second closing path; plan_overlap is tunable; the synthesize directive ignores stale-open items so a mis-tracked item never blocks the final answer.
- **harvest_findings only yields url-bearing web results; a research item answered from execute_code or pure reasoning produces no [src:] and never auto-checks, leaving it perpetually open.** → PLAN-DONE fallback closes url-less items; the 'All items researched — synthesize now' directive at 0-open is complemented by a synthesize path that ignores stale-open items after the model signals done via /research done.
- **Active-recall x anti-disclosure leak: when asked 'how do you know?' the model reveals 'my notes/memory/the system told me', or the injected t#NNNNN invites 'the system told me t#42'.** → Never relax prohibition (ii): _BLOCK_HEADER stays verbatim on warm turns and _BLOCK_HEADER_RESUME re-attributes continuity to remembering; recall ONLY user-stated facts (honestly 'earlier in our conversation'), findings stay under [src:] and are never surfaced as 'you told me'; gate go-live on an empirical leak-rate probe reusing the round-2 disclosure experiment.
- **Stale rec['_resumed'] on a long-lived record could leak the topic id on a warm turn.** → Explicitly set rec['_resumed']=False on EVERY non-resume path in _route (single-open continuation, classify-route, fresh open, override new/route branches), not only on the resume ones; the flag is transient and never serialized (_serialize_topic_md fixed key set).
- **Prompt-budget blowout: multiple injected sections (plan, scratch, facts, findings) truncate the anti-disclosure header or starve src-findings.** → block_token_cap stays the SINGLE combined cap enforced by the existing tail-truncate(1143); plan_token_cap is CARVED FROM it (not additive); section order drops plan/scratch before src-findings/header; bump default 250->320 only when a section flag is on; F1's FORCE_VERIFY_NOTE is a separate ~90t cache-stable system append — no shared budget, no cached-prefix churn.
- **Prompt-injection persistence: scratchpad storing a raw tool_result body lets an injected instruction survive into future turns and the durable store.** → Reuse selfheal.strip_tool_result_wrapper (v1.7.2 untrusted-envelope peel) and store only short first-lines / title—url, never the raw body; scratch capture is read-only post-hoc over conversation_history.
- **Autostore _extract_facts and _seed_plan add LLM calls on the already-saturated shared vLLM box, adding latency/load; autostore could also hallucinate or over-capture durable PII into llm-wiki.** → _seed_plan is one-shot (opening turn only, decompose off by default); autostore is amortized (autostore_every=4) with temp 0 / short max_tokens / timeout / schema-constrained first-person durable-only, default OFF, inbox-only behind the human merge gate; skip when loadaware reports SLOW/STALLED; steady state stays <=2 aux calls/turn (classify+curate).
- **Fail-safety regression: a new call path raising breaks a stock turn, or off-state drifts from byte-identical.** → Every new function is flag-gated first and wrapped like the existing ones (return None/'' on error) inside build_topic_block's existing try/except; the _in_background_review guard is retained; a regression gate proves off=byte-identical (tests 118-120, 686-688 stay green) before each phase ships.

## Open decisions
- **Two fragments use 'scratchpad' for different things: F1 means the plan-checklist, F3 means captured non-src notes.** → Adopt BOTH as distinct complementary sections in the same topic record — ## plan (goal decomposition + progress) and ## scratchpad (working notes). Reserve the word 'scratchpad' for the notes bucket and call F1's structure the 'research plan' to remove ambiguity in flags and docs.
- **Flag proliferation: 11 new knobs under tools.tool_search.topics.*.** → Ship them as independent knobs for granular rollback but group under four masters (research, resume_surface, active_recall, autostore); document that the sub-knobs (plan_max_items, plan_token_cap, plan_overlap, recall_facts_max, autostore_every) inherit their master's off-state. Consider collapsing research_decompose into research once the decomposition call is validated.
- **One combined block_token_cap vs per-section sub-budgets for the injected block.** → Keep ONE combined cap enforced by the existing tail-truncate; carve plan_token_cap as a sub-budget WITHIN it (never additive); bump the default 250->320 only when a section flag is on. Reject a separate additive scratchpad cap — it would risk truncating the anti-disclosure header.
- **Whether to enable heuristic auto-detection of research intent (research_auto).** → Default OFF; only promote an already-open topic on its FIRST turn; implement a NEW research_intent() multi-item detector in verify_route.py and explicitly do NOT reuse attribution_recency_intent (it fires on single checkable facts and would mislabel citation questions). Validate the false-positive rate on tests/corpus.yaml before anyone enables it.
- **Whether autostore should auto-populate durable user facts at all, given PII-into-wiki risk.** → Yes but default OFF, inbox-only behind the human merge gate, schema-constrained first-person durable-only at temp 0, amortized; never write wiki/ directly. Gate go-live on a review of captured facts in a tmp-vault run.
- **Residual disclosure-leak risk from injecting the real t#NNNNN on a resume.** → Ship behind resume_surface default off; measure the disclosure-leak rate on the 'how do you know?' probe (reuse the round-2 experiment harness) before enabling; _BLOCK_HEADER_RESUME keeps the mechanism-silence clause verbatim and the SOUL paragraph re-attributes continuity to remembering.
- **Where the model closes a research item that produced no URL.** → Three-tier: primary = keyword-overlap reconcile on sourced findings; secondary = opt-in PLAN-DONE:<text> parsed from assistant_response; tertiary = a synthesize directive that ignores stale-open items so an unclosable item never blocks the final cited answer.
